# Reproduce GENCO §5.4.2 (Power Flow on datakit)

This covers the residual-vs-grid-size plot (`fig:gridsize_vs_residuals_pf`). The runtime figures and speedup columns are in [GENCO](5.4.2-3_Runtime_genco.md) and [PowerModels](5.4.2-3_Runtime_powermodels.md).

GENCO Base / Small / Tiny are trained from scratch on each grid. Hidden size is 48 / 24 / 12.

## 1. Saved results

The GENCO numbers used in the figure are already saved on this branch: [scripts/datakit_pf/results](https://github.com/gridfm/gridfm-graphkit/tree/genco-paper-repro/scripts/datakit_pf/results).

`scripts/datakit_pf/results/pf_eval_combined_eval_metrics.csv` is one row per grid, size, and seed. `pf_eval_aggregated.csv` is the mean and sample standard deviation (`ddof=1`) plotted in the figure.

For grids through GOC 500, `seed1` / `seed2` / `seed3` in that CSV are YAML seeds `0` / `1` / `42`. For GOC 2000 and GOC 10000 the CSV seed is the YAML seed (`0` and `42` on GOC 2000; `0` and `1` on GOC 10000). The seeds are different because different people in the team ran the experiments and we did not agree on seeds beforehand :D.

Base is included through GOC 500. Small and Tiny are included through GOC 10000.

To generate the figures and tables from these saved results, jump to [Figures and tables](#6-figures-and-tables).

```bash
TORCH_CUDA_VERSION=$(python -c "import torch; print(torch.__version__ + ('+cpu' if torch.version.cuda is None else ''))")
```

## 4. Training

Use this graphkit branch and these configs. The paper results were obtained with [genco-paper-repro](https://github.com/gridfm/gridfm-graphkit/tree/genco-paper-repro); we only guarantee the same numbers on this branch, because `main` is under active development.

- Branch: [genco-paper-repro](https://github.com/gridfm/gridfm-graphkit/tree/genco-paper-repro)
- Configs: [scripts/datakit_pf/configs](https://github.com/gridfm/gridfm-graphkit/tree/genco-paper-repro/scripts/datakit_pf/configs) (`<network>_{base,small,tiny}_seed<seed>.yaml`)

Through GOC 500 the seeds are `0`, `1`, and `42`, for Base, Small, and Tiny. GOC 2000 is Small and Tiny, seeds `0` and `42`. GOC 10000 is Small and Tiny, seeds `0` and `1`.

```bash
gridfm_graphkit train \
  --config scripts/datakit_pf/configs/case118_ieee_base_seed0.yaml \
  --data_path data
```

Repeat for the other configs. Each YAML sets the grid, hidden size, and seed.

## 5. Evaluating the paper checkpoints

You can also reuse our saved models

**Checkpoints:** [gridfm/genco-pf-datakit](https://huggingface.co/gridfm/genco-pf-datakit)

Weights: `<network>/{base,small,tiny}/seed<seed>/best_model_state_dict.pt` plus `normalizer_stats.pt`, except GOC 10000, which uses `last.pt`. Grids through GOC 500 and GOC 2000 were scored on the best-validation state dict (which is the default behavior when using the metrics from the evaluation done with the `eval` command). GOC 10000 was scored on the last-epoch weights (`last.pt`, extracted from Lightning `last.ckpt`), which is what is ran automatically at the end of a training job. The resullts with the best saved model might be slightly different, but there are within noise. The training YAML for that run sits in the same folder. 

The MLflow runs are in the same repo under [mlflow/](https://huggingface.co/gridfm/genco-pf-datakit/tree/main/mlflow). For grids through GOC 500 the figure uses [mlflow/eval/](https://huggingface.co/gridfm/genco-pf-datakit/tree/main/mlflow/eval). For GOC 2000 and GOC 10000 it uses [mlflow/train/](https://huggingface.co/gridfm/genco-pf-datakit/tree/main/mlflow/train).

There is no separate eval YAML. Reuse the train config.

```bash
hf download gridfm/genco-pf-datakit --include "case118_ieee/base/seed0/**" --local-dir genco-pf-datakit

gridfm_graphkit evaluate \
  --config scripts/datakit_pf/configs/case118_ieee_base_seed0.yaml \
  --data_path data \
  --model_path genco-pf-datakit/case118_ieee/base/seed0/best_model_state_dict.pt \
  --normalizer_stats genco-pf-datakit/case118_ieee/base/seed0/normalizer_stats.pt
```

Repeat for the other grids, sizes, and seeds. For GOC 10000, pass `last.pt` instead of `best_model_state_dict.pt`.

From the graphkit repo root (`pip install -e .` already pulls in pandas and matplotlib). Script: [plot_grid_scaling_active_residuals_pf.py](https://github.com/gridfm/gridfm-graphkit/blob/genco-paper-repro/scripts/datakit_pf/plot_grid_scaling_active_residuals_pf.py).

```bash
python scripts/datakit_pf/plot_grid_scaling_active_residuals_pf.py
```
