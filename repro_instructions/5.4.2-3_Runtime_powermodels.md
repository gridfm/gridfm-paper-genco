# Reproducing the GENCO paper (PowerModels runtime)

Classical-solver runtime for the [GENCO paper](https://arxiv.org/abs/2608.09921): amortized per-instance wall time for AC-PF, DC-PF, AC-OPF, and DC-OPF implemented in PowerModels.

There are two protocols, as in [5.4.2-3_Runtime_genco](5.4.2-3_Runtime_genco.md). **In-memory** (setup 1) solves the corrected base `.m` case already in memory. **From-disk** (setup 2) parses one scenario per solve and uses datakit data. Init, compile, and `/tmp` staging are outside the timed work.

## 1. Saved results

The classical-solver timings used in the paper are already saved on [genco-paper-repro](https://github.com/gridfm/gridfm-datakit/tree/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix).

The 56 committed CSVs are already saved. They are the paper raw results. Re-run the jobs only to regenerate them. GENCO GPU numbers are produced from [5.4.2-3_Runtime_genco](5.4.2-3_Runtime_genco.md), not from this tree.

They live at [scripts/runtime/outputs_julia/full_matrix/](https://github.com/gridfm/gridfm-datakit/tree/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix). `{small,large}/setup1/` is the in-memory sweep. `{small,large}/setup2/` is the from-disk sweep. `wall_at_best_p_*.csv` is derived from those sweeps.

Amortized per-instance runtime is `pf_elapsed_s / n_pfs`. Best `p` is the minimum of that ratio. Init, compile, and `/tmp` staging are outside `pf_elapsed_s`.

To generate the figures and tables from these saved results, jump to [Figures and tables](5.4.2-3_Runtime_genco.md#5-figures-and-tables).

## 2. Data

Setup 1 uses the seven corrected `.m` files in [gridfm_datakit/grids/](https://github.com/gridfm/gridfm-datakit/tree/genco-paper-repro/gridfm_datakit/grids) (tracked on this branch).

Setup 2 parses one datakit scenario per solve. The scenarios are already saved as PowerModels JSON and corrected so they can be parsed and loaded as fast as possible. The 10,000 corrected JSON files per grid are [gridfm/genco-powermodels-runtime](https://huggingface.co/datasets/gridfm/genco-powermodels-runtime).

```bash
hf download gridfm/genco-powermodels-runtime --repo-type dataset --local-dir /path/to/powermodels-runtime
export GRIDFM_DATA_BASE=/path/to/powermodels-runtime
```

To build that JSON from parquet instead, run [scripts/convert/batch_convert_powermodels.py](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/convert/batch_convert_powermodels.py) and then [run_correction.sh](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/pure_julia/run_correction.sh).

## 3. Install

```bash
git clone -b genco-paper-repro https://github.com/gridfm/gridfm-datakit.git
cd gridfm-datakit
julia --project=scripts/runtime/pure_julia -e 'using Pkg; Pkg.instantiate()'
```

Run every command below from that repository root. Any recent Julia is fine. A rerun needs this Julia project. Rebuilding the figures does not. The plots are obtained with the commands in [5.4.2-3_Runtime_genco](5.4.2-3_Runtime_genco.md). Paper jobs used Julia 1.12.6. That install uses [pure_julia/Manifest.toml](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/pure_julia/Manifest.toml). Pins, Ipopt/MUMPS, threads, and hardware are in [environment_versions.md](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix/environment_versions.md).

## 4. Evaluating the paper checkpoints

There is no saved checkpoint to evaluate. This step re-runs the solver matrix. `--resume` is on: delete a CSV to recompute that cell.

**Setup 1 (in-memory)** solves a unique base `.m` case repeatedly with [run_matrix.jl](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/pure_julia/run_matrix.jl).

```bash
julia --project=scripts/runtime/pure_julia scripts/runtime/pure_julia/run_matrix.jl --scope small --setup setup1
julia --project=scripts/runtime/pure_julia scripts/runtime/pure_julia/run_matrix.jl --scope large --setup setup1
```

**Setup 2 (from-disk)** uses `GRIDFM_DATA_BASE` from the data section.

```bash
julia --project=scripts/runtime/pure_julia scripts/runtime/pure_julia/run_matrix.jl --scope small --setup setup2
julia --project=scripts/runtime/pure_julia scripts/runtime/pure_julia/run_matrix.jl --scope large --setup setup2
```

On LSF, [submit_matrix.sh](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/pure_julia/submit_matrix.sh) submits setup 1 and setup 2 (84 cores; 256G small / 960G large).

## Notes

- Ipopt: `max_iter=100`, `tol=1e-6`, linear solver MUMPS (default; not ma57). One BLAS thread per worker (`JULIA_NUM_THREADS=1` and matching OpenBLAS/OMP/MKL flags in `pure_julia/env.sh`).
- Original hardware: AMD EPYC 9634, 84 cores. Details: [environment_versions.md](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix/environment_versions.md).
- Observed job RAM: small ~205 GB, large ~870 GB. See [lsf_job_wall_times.md](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix/lsf_job_wall_times.md).
- Full parameter table: [methodology_parameters.md](https://github.com/gridfm/gridfm-datakit/blob/genco-paper-repro/scripts/runtime/outputs_julia/full_matrix/methodology_parameters.md).
